## Purpose

Platform-adaptive workspace root paths and UUID-based workspace directory naming for cross-platform compatibility.

## Requirements

### Requirement: Platform-adaptive workspace root

The system SHALL select a default workspace root path appropriate to the host operating system when `WORKSPACE_ROOT` is not set. The path SHALL be outside the project directory and writable without elevated privileges.

#### Scenario: Default root on macOS
- **WHEN** the system starts on macOS without `WORKSPACE_ROOT` configured
- **THEN** the default root SHALL be `~/Library/Application Support/opencode-orchestrator/workspaces` and the directory SHALL be created if it does not exist

#### Scenario: Default root on Linux
- **WHEN** the system starts on Linux without `WORKSPACE_ROOT` configured
- **THEN** the default root SHALL be `~/.local/share/opencode-orchestrator/workspaces` and the directory SHALL be created if it does not exist

#### Scenario: Default root on Windows
- **WHEN** the system starts on Windows without `WORKSPACE_ROOT` configured
- **THEN** the default root SHALL be `%APPDATA%/opencode-orchestrator/workspaces` and the directory SHALL be created if it does not exist

#### Scenario: WORKSPACE_ROOT env var override
- **WHEN** `WORKSPACE_ROOT` is set in the environment
- **THEN** the system SHALL use the configured value instead of the platform default

### Requirement: UUID-based workspace directory

The system SHALL create workspace directories using a UUID-based path that is stable across workspace renames. The workspace `id` field SHALL be pre-generated (not auto-generated by Prisma) and used as the unique path segment.

#### Scenario: Generate workspace ID before path creation
- **WHEN** `workspace.service.create()` is called
- **THEN** the system SHALL generate a UUID v4 before constructing the workspace directory path

#### Scenario: Path structure
- **WHEN** a workspace directory is created
- **THEN** the path SHALL be `{WORKSPACE_ROOT}/{tenantId}/{workspaceId}` where `tenantId` is the tenant's database ID and `workspaceId` is the pre-generated UUID
- **AND** the path SHALL NOT contain the workspace `name`

#### Scenario: Path stored in database
- **WHEN** a workspace is created
- **THEN** the `workDir` field SHALL contain the full absolute path
- **AND** the path SHALL be used for Docker volume mounts

#### Scenario: Rename does not affect path
- **WHEN** a workspace is renamed via `workspace.service.update()`
- **THEN** the `workDir` field SHALL remain unchanged
- **AND** the directory on disk SHALL NOT be moved or renamed

### Requirement: Bootstrap directory creation

The system SHALL ensure the workspace root directory exists at application startup.

#### Scenario: Create root directory on start
- **WHEN** the application boots
- **THEN** `mkdirSync(WORKSPACE_ROOT, { recursive: true })` SHALL be called to guarantee the root exists
- **AND** the operation SHALL be idempotent (no error if directory already exists)

#### Scenario: Root creation failure
- **WHEN** the workspace root directory cannot be created
- **THEN** the application SHALL log a warning and continue (workspace creation will fail later with a clear error)
