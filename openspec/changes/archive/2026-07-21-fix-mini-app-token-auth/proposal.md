## Why

The Telegram Mini App is non-functional when opened via token-based auth links generated by the bot (`?token=ma_xxx`). The server validates the token and serves the page, but the frontend never receives the auth string, so all subsequent REST API calls and WebSocket connections fail with 401. Additionally, "Open in Mini App" buttons generated during active sessions lack token auth entirely, and navigation to the relevant session is missing.

## What Changes

- Fix `mini-app.controller.ts` to pass the validated auth token (not the raw query param) in `window.__INITIAL_STATE__`
- Fix `app.js` auth precedence to use the token from initial state as the primary auth mechanism, falling back to `tgWebApp.initData`
- Extend auth token expiry from 5 minutes to 60 minutes
- Add tokens to all "Open in Mini App" bot buttons that currently lack them
- Add auto-navigation from `?session=` URL param to the session terminal on page load
- Fix WebSocket gateway to route keyboard input to the correct session (by connected session ID, not user's "current" session)
- Fix unhandled promise rejection in WebSocket input handler
- Add user ownership checks to session cancellation and detail retrieval endpoints
- Fix model loading condition (gate on provider, not projects)
- Fix HTML-escaping misuse in onclick attribute values

## Capabilities

### New Capabilities

- `token-auto-navigate`: Auto-navigate to a session terminal from URL query parameter when opening the Mini App via a bot-generated link

### Modified Capabilities

- `mini-app-serve`: Auth flow changes — the `initData` string injected into `window.__INITIAL_STATE__` must be the validated auth string (token or Telegram initData), not the raw URL query param. Support all three auth sources (`tgWebAppData`, `initData`, `token`) equivalently.
- `mini-app-api`: Auth method broadened — the `X-Telegram-Init-Data` header now accepts our custom `ma_` prefixed HMAC token in addition to Telegram WebApp initData. Session endpoints must enforce user ownership.
- `mini-app-gateway`: WebSocket auth now accepts the custom token via `initData` query param. Input routing must use the connected session ID, not the user's current session. Promise rejection handling.
- `mini-app-ui`: Auth precedence changed — token from server-injected state takes priority over `tgWebApp.initData`. On-page-load session auto-navigation from URL param. Model loading gated on provider, not projects. onclick value escaping corrected.
